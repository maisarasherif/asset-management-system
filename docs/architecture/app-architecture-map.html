07 / Critical workflows

Where architecture becomes behavior

These flows cross enough boundaries to define the system more accurately than a directory list.

Session-authenticated request

  1. Cookie or bearer token reaches Gin.
  2. JWT is validated.
  3. User must be active and the token must match the stored current session.
  4. Global/product/client access middleware authorizes.
  5. Controller runs typed SQL and returns JSON, blob, or URL.

Asset spin-up from template

  1. Admin submits asset + optional template.
  2. PostgreSQL transaction creates the asset.
  3. UUID spin-up function materializes components and pending certificates.
  4. Commit publishes one coherent live structure.
  5. Frontend invalidates asset/template query keys.

Certificate document lifecycle

  1. Multipart upload is validated.
  2. File streams to an opaque, date-partitioned R2 key.
  3. Certificate reference and upload audit are persisted.
  4. Competent-person attribution is retained.
  5. Authorized reads receive a five-minute signed URL.

Durable notification delivery

  1. Startup, cron, manual run, or maintenance threshold finds a candidate.
  2. A per-tier/channel idempotency key claims a delivery row.
  3. River job insert shares the database transaction.
  4. Worker calls SMTP or ClickUp.
  5. Delivery becomes SENT, retriable failure, or final FAILED.

HR/Admin renewal

  1. User creates or renews a compliance record.
  2. A new version is appended; the former current version is superseded.
  3. Type policy or product default supplies reminder days.
  4. Renewable active records enter expiry scans.
  5. Archived subjects/records and one-time types are excluded.

Password reset

  1. Rate-limited request creates a hashed single-use token.
  2. Reset payload is AES-GCM encrypted before job insertion.
  3. River sends the email.
  4. Reset endpoint consumes the token and updates the password.
  5. Stored sessions are revoked.
08 / Security model

Defense is layered by boundary

Frontend route guards are navigation policy. Backend middleware and scoped SQL are the actual enforcement boundary.

Authentication

Revocable JWT session

  • 6-hour signed JWT
  • HTTP-only SameSite=Lax cookie
  • Secure outside development
  • Bearer fallback
  • Current token stored on user row
Authorization

Four checks

  • Active user status
  • Global role
  • Product Access + role
  • Project/resource-scoped query
Files + public APIs

Short-lived exposure

  • Opaque object keys
  • Safe download filenames
  • 5-minute signed URLs
  • Login/reset rate limits
  • Metrics closed when unconfigured
Architecture drift: the root ARCHITECTURE.md still states MongoDB and bearer-token-only authentication. The current code uses PostgreSQL/sqlc and an HTTP-only cookie-first session with bearer fallback.
09 / Operations + quality

Durability, observability, regression

The process starts both scans immediately, then schedules them daily at 08:00 by default. River and delivery tables retain operational evidence.

Background engine

River on PostgreSQL

Three worker kinds: password reset email, notification email, and notification ClickUp. Jobs retry up to five attempts; River UI is SUPER_ADMIN-only.

Observability

Request and delivery visibility

Zerolog + request IDs; Prometheus request total, latency, and in-flight metrics; health endpoint; product-scoped task/failure pages; River UI.

Deployment gap

Runtime packaging is not declared

No production container or orchestrator manifest was found. Reverse proxy, secrets delivery, backups, process supervision, and horizontal scaling remain outside this repository.
